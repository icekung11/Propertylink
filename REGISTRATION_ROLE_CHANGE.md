Real register -> verify development OTP -> password login -> session cookie -> role dashboard -> logout/revocation checks passed for all four roles (45/45 including cleanup). Registration testing also exposed an existing storage mismatch: otp_verifications.otp_code was varchar(10), but registration writes a 64-character SHA-256 digest. Widen that column to varchar(64) with prisma/manual/registration-otp-hash.sql and update Prisma's native type. This preserves existing values and constraints and fixes registration for every role; keep hashed OTP verification and the five-attempt limit.

The operator explicitly requested restoring Owner and Admin to public Register without invitations. Add both choices and accept all four role codes in registration, retaining one role, password/consent checks, pending verification, OTP and existing login role checks.

Create the OTP before assigning the role in the same registration transaction. All existing-account Admin assignments retain the Owner requirement. No trigger is disabled; no table/constraint/policy is removed, and no existing user role is changed. Apply only prisma/manual/register-admin-self-assignment.sql; do not replay migrations.
