## Project Evidence

## Post-audit implementation status (2026-10-20)

- `GET /api/listings` now always limits public results to `APPROVED`; homepage and `/properties` consume this endpoint instead of `PUBLIC_PROPERTIES`.
- Session guard now requires HS256 signed sessions configured by `AUTH_SECRET`, checks current DB account/role/status, and ignores `x-user-id`. `AUTH_SECRET` is not configured, so login is unavailable until the operator provides it.
- `POST /api/inquiries` is implemented; app context persists inquiry/favorite/notification changes through APIs.
- Several contracts remain partial or blocked: SMS OTP provider and image storage are absent; runtime DB role bypasses RLS; live migrations have no registry and diverge from checked-in SQL; dashboards/workflows still consume sample data. See `IMPLEMENTATION_PLAN.md` and `API_TEST_REPORT.md`.

## Phase 2/3 correction

- Historical rows above record Phase 0 status. The target app pages no longer import sample data; public/home, seller, buyer, admin, and owner pages use their APIs (source search verified).
- `/api/admin/listings/pending` and moderation now require signed role auth. `POST /api/listings` uses session identity and public GET fixes APPROVED status. Inquiry status/message APIs were added and user-scoped via transaction context.
- `GET /api/seed-mock` now returns 410. Authenticated behavior is not runtime verified: the current `propertylink_app` URL in `.env` fails PostgreSQL authentication. Anonymous route checks and the build results are in `API_TEST_REPORT.md`.

- Framework เป็น Next.js 15.1.0 (ไม่ใช่ Vite ตาม AGENTS.md ที่แนบมา); `package.json` scripts มี `dev`, `build`, `start`, `lint` แต่ไม่มี test/typecheck script.
- API อยู่ใน `src/app/api`; Prisma client อยู่ `src/lib/prisma.ts`; transaction context อยู่ `src/lib/db-session.ts`; auth guard อยู่ `src/lib/auth-guard.ts`; error mapping อยู่ `src/lib/db-errors.ts`.
- Live DB read-only introspection สำเร็จ: `propertylink_db.public`, 20 base tables, 10 functions, 11 triggers (unique trigger names), 3 policies; RLS enabled บน `audit_logs`, `inquiries`, `user_consents` בלבד. Current records counts: users 8, listings 7, categories 5, locations 4, roles 4, inquiries 0; 0 users currently have multiple roles.
- Live DB มี triggers/functions สำหรับ OTP+active check ตอนสร้าง listing, image count, admin self-approval, listing rate check, owner-only admin assignment, inquiry notifications/contact history และ status history. `fn_check_listing_rate_limit` จำกัด insert listings ใน rolling 24h ไม่ใช่ submit-per-calendar-day.
